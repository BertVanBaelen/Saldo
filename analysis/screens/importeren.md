# Importeren (wizard)

Analysis: 4.6, 12 (screen 9) · Design: in the mockup (`finance-mockup/importeren.html`, `js/screens/importeren.js`), derived from the analysis, not on the design boards · Concepts: [import](../concepts/import.md), [category](../concepts/category.md), [transaction](../concepts/transaction.md) · Phases: [0.1-7](../../plan/v0.1-mockup/07-missing-designs.md), [0.1-8](../../plan/v0.1-mockup/08-review-and-freeze.md), [0.3-6](../../plan/v0.3-bank-sync/06-csv-import.md), [0.5-2](../../plan/v0.5-bilance-import/02-import-wizard.md), [0.5-3](../../plan/v0.5-bilance-import/03-category-mapping.md), [0.5-4](../../plan/v0.5-bilance-import/04-overlap-and-duplicates.md), [0.5-5](../../plan/v0.5-bilance-import/05-batches-and-undo.md)

## Content to design
File → column mapping → **category mapping table** (source category, transactions, total, target) → preview with probable duplicates and import cutoff → result with undo.

**In 0.3-6** (built 9 Nov 2026, `web/src/pages/Importeren.tsx`): the wizard has four steps, *Bestand* (what the server found in the file), *Kolommen* (the column mapping and the target account), *Controle* (counts: new, already in Saldo, unreadable) and *Klaar* (the batch), plus the import history on the start view. The designed wizard still lacks the category mapping table, probable duplicates per row and the import cutoff, undo, the Bilance preset, and importing into a new account (the empty state of the mockup); they come in [0.5](../../plan/v0.5-bilance-import/README.md).

**In 0.5-2** (built 11 Nov 2026): five steps as in the mockup, *Bestand*, *Kolommen*, *Categorieën*, *Controle* and *Klaar*. The Bilance preset is recognised from the header; the settings the mockup shows are built (scheidingsteken and codering in *Bestand*, datumnotatie and decimaalteken in *Kolommen*, each with a detected or "Automatisch" default the user can override); the columns step has fields for the note, the two category parts and the account name, and a file with an account name column replaces the single target account by a table that maps each name to one of the user's accounts ("accounts from a column"). *Categorieën* lists the distinct (Categorie, Subcategorie) pairs of the file with their transactions and total, read-only, with a note that mapping them comes in 0.5-3; without a category column it says so and does not block. Deviations from the mockup: no "Eén rekening / Uit de kolom" switch (choosing the Rekeningnaam column is the switch), no "Nieuwe handmatige rekening" and no "Niet importeren" per name (an unmapped name blocks), no "Saldo leest" reading of the sample in the columns table (it shows the example cells), and ISO-8859-1 is not offered next to Windows-1252.

**In 0.5-3** (built 11 Nov 2026): *Categorieën* maps the pairs of the file onto Saldo's category tree, as in the mockup: per pair the count, the total and the shared dropdown with Niet categoriseren, Nieuwe categorie and the tree with icons; the saved mapping is pre-selected with *Opgeslagen*, a suggestion by name with *Voorstel*; the same target on several pairs shows "Samen met ..." and the *Samengevoegd* card; *Per hoofdcategorie koppelen* gives all pairs of a main category one target; *Nieuwe categorie* asks for a name, a place (a main category or a new main category) and an icon. *Controle* and *Klaar* say how many rows get a category and how many stay without; the mapping is saved with the import. Deviations from the mockup: the badge says *Opgeslagen* (mockup *Bewaard*), the closed dropdown has no colour dot, a pair with no match starts on Niet categoriseren (mockup: a new category), the new category has a parent choice and the icon picker, and a mixed main category starts on Niet categoriseren in "per hoofdcategorie". The mockup's mapping dialog on a batch (edit and re-apply) is not built; the API for it is ([docs/api.md](../../docs/api.md)), the screen comes with batches in 0.5-5.

**In 0.5-4** (built 11 Nov 2026, `ImporterenControle.tsx`): for a Bilance file *Controle* replaces the 0.3-6 overlap warning by the cutoff and the probable duplicates, as in the mockup. Per target account a card *Afkapdatum* with a date field filled in with the first synced date of the account (badge *Voorstel*; a link back to it after a change; *Geen afkapdatum* clears it; an account that syncs nothing says so and starts empty), and the stats *nieuw*, *na afkapdatum*, *waarschijnlijke dubbels*. *Waarschijnlijke dubbels* lists each pair side by side (*In het bestand* ≈ *Al in Saldo*, with the date, name, amount, the file's category and the stored row's category or *Niet gecategoriseerd* with *krijgt ...* when it takes the category over), why it matches, and a toggle *Toch importeren* (default off; the first four are shown, *Toon alle*), plus *Alles opnemen*. The result lists the rows skipped after the cutoff, the probable duplicates skipped (and how many were imported anyway), the existing transactions that took their category, and the unreadable rows. A generic CSV keeps the 0.3-6 warning and has no cutoff. Deviations from the mockup: the field is labelled *Afkapdatum* (mockup *Importeren tot*) and the stat *na afkapdatum* (mockup *na de grens*); there is no switch to turn the category take-over off (it only ever fills a transaction without category); the list shows at most 200 pairs and *Alles opnemen* covers those; the *Al in Saldo* tag says *uit een import* or *van de bank* (no batch number yet); the arrow of *krijgt* is the chevron icon; the cutoff is a date on or after which rows are skipped (the mockup's *Importeren tot* reads as the first day not imported as well); the existing category shows its name and icon, not the path.
