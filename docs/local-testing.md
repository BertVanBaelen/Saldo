# Local testing

How to run Saldo on your own machine with the demo story, reset it, and click through every screen in about ten minutes. Needs Go and Node on the PATH. Developer tests (`go test`, `npm test`) are in [architecture.md](architecture.md); this page is about trying the app by hand.

## Start, reset, stop

```powershell
pwsh -File scripts/dev.ps1           # start
pwsh -File scripts/dev.ps1 -Fresh    # delete the demo database first: the demo story starts over
pwsh -File scripts/dev.ps1 -Stop     # stop what an earlier run left running
```

Windows PowerShell works too (`powershell -File scripts/dev.ps1`). Ctrl+C in the window that runs it stops everything. The script:

- builds the server to `server/bin/saldo.exe` and runs that (a `go run` child would survive a stop), and installs the web app's packages with `npm ci` when `web/node_modules` is missing;
- keeps the demo database and the server log in **`server/data-demo/`** (`server.log`, `server.err.log`). That folder is only for demo mode; `server/data/` (the default of a non-demo run) is never touched, and `-Fresh` deletes `server/data-demo/` and nothing else;
- checks first that ports 8080 and 5180 are free. If not, it says which program holds the port and what to do: `scripts/dev.ps1 -Stop` when it is an earlier run of this script, otherwise close that program. Nothing is started in that case;
- waits until http://localhost:8080/api/health answers, then prints the URLs and "Saldo is ready".

## The two URLs

| URL | What |
|---|---|
| http://localhost:5180 | The web app with hot reload (Vite). Open this one. It forwards `/api` to the server. |
| http://localhost:8080 | The Go server: the JSON API of [api.md](api.md) (try `/api/health`). It serves the built web app only when `SALDO_WEB_DIR` points at `web/dist`; otherwise `/` shows a short notice. |

## Demo mode

`SALDO_DEMO=1` (set by the script):

- Seeds the demo story: you are **Bert**; Partner exists but you never see their own account. Bert has Zichtrekening (Argenta, bank), Spaarrekening and Reserve (manual savings) and the Gedeelde rekening shared with Partner; about a year of transactions, from November 2025 to 18 November 2026 (342 in all, Partner's own account included).
- Acts as Bert on every request, **without signing in**, and refuses to start on a database that holds non-demo data (that is why it has its own folder).
- The date is fixed at **18 November 2026** ("vandaag" in the app). A CSV file may not hold rows dated after it. The history on Importeren shows the real date of an import, not the demo date.
- "Nu synchroniseren" only records a sync: no new transactions arrive, and a second press within 15 minutes answers "Je hebt net gesynchroniseerd. Probeer het over 15 minuten opnieuw."
- **The demo IBANs are invalid on purpose** (wrong check digits, so they can never be a real account). Consequences for importing: a `Rekening` cell in a CSV cannot hold a demo account's IBAN, because the importer refuses a row whose account is not a valid IBAN ("De rekening in het bestand is geen geldig IBAN."). So the files for the demo bank account leave that cell empty, and the files that test the account check carry a valid documentation IBAN and go into a manual account that you create with that IBAN (step "Rekeningen" below). The server also refuses a demo IBAN on a new manual account.
- The 4 transactions to categorise stay as they are (Bol.com pending, Bakkerij De Graankorrel, Frituur 't Pleintje, Apotheek Van Damme): the demo's numbers are used by tests and the design. More uncategorised rows with recognisable counterparties (Colruyt, Delhaize, Lidl, Luminus, Proximus, Netflix, NMBS, Kinepolis, a pharmacy, rent, salary) come from the CSV files in [`fixtures/csv/`](../fixtures/csv/README.md): invented data, one file per case.

## Click-through (about ten minutes)

Start with `pwsh -File scripts/dev.ps1 -Fresh` and open http://localhost:5180. Each item is "do this, you should see that". The last step changes the demo state; `-Fresh` restores it.

### Start (1 minute)
1. Open **Start**. You see the scope switch "Alles", "Persoonlijk", "Gedeeld" and two alerts: "Toestemming verloopt over 12 dagen" and "4 transacties te categoriseren".
2. "Saldo nu · alle rekeningen" shows € 2.914,90, "Samen, ter info · zonder spaarrekeningen", with the tiles Zichtrekening € 1.968,82 (€ 1.069 boven buffer) and Gedeelde rekening € 946,08 (€ 346 boven buffer). Below: "Persoonlijke rekeningen" (Zichtrekening, Spaarrekening, Reserve) and "Gedeelde rekeningen".
3. Click "Persoonlijk": "Saldo nu · Zichtrekening" with € 1.968,82 and no shared account. Click "Gedeeld": "Saldo nu · Gedeelde rekening" € 946,08, "Met Partner · jij bent beheerder". Back to "Alles".
4. Press the sync icon ("Nu synchroniseren"): the bar spins and a toast "Gesynchroniseerd" appears.
5. Click the alert "4 transacties te categoriseren": Transacties opens with the "Niet gecategoriseerd" filter on.

### Transacties (2 minutes)
1. The sidebar badge next to Transacties reads 4. Without filters the list starts with "Vandaag · woensdag 18 november": Bol.com ("In behandeling") and Colruyt Laagste Prijzen.
2. Click the chip "Niet gecategoriseerd 4": exactly Bol.com, Bakkerij De Graankorrel, Frituur 't Pleintje and Apotheek Van Damme. Click it again to switch it off.
3. Search ("Zoek op naam, bedrag of mededeling"): `colruyt` shows only Colruyt Laagste Prijzen rows, all on the Gedeelde rekening; `86,42` shows only rows of exactly € 86,42; clear the box.
4. Click a row. The detail (a side panel on a wide screen, a sheet on a phone) shows the amount, "Datum", "Mededeling" and "Categorie"; the pending Bol.com row adds "Nog in behandeling. Telt mee in de totalen zodra de bank ze boekt."
5. Filters: the chip "Alle rekeningen" → "Zichtrekening" leaves only that account's rows (the address becomes `?rekening=1`); the chip "Periode" → "Vorige maand" then leaves 1 to 24 October 2026; "Wis filters" removes both. "Oudere transacties laden" at the bottom loads the next 50.

### Rekeningen (2 minutes)
1. Open **Rekeningen** (sidebar, group Beheer). "Buffer per rekening" shows € 1.500,00 samen; PERSOONLIJK lists Zichtrekening (Buffer € 900,00, € 1.968,82), Spaarrekening (€ 12.500,00) and Reserve (€ 4.200,00); GEDEELD lists Gedeelde rekening (€ 946,08).
2. Add a manual account, which the import step below needs: "Rekening toevoegen" → "Handmatige rekening". Name `Testrekening`, Soort "Zichtrekening zonder bankkoppeling", IBAN `BE68 5390 0754 7034` (a documentation IBAN with valid check digits), "Saldo vandaag" `500,00`, press "Toevoegen". A toast "Testrekening toegevoegd" appears and Testrekening shows under PERSOONLIJK as "Handmatig · bijgewerkt 18 nov" with € 500,00. (Typing a demo IBAN such as `BE68 0000 0000 4821` instead gives "Dit lijkt geen geldig IBAN. Kijk het na of laat het leeg.")
3. Click Zichtrekening, then "Details en synchronisatie": the account page shows "Saldo nu", the masked IBAN `BE68 •••• •••• 4821`, "Recente transacties", and "Synchronisatie" with "Opnieuw autoriseren" and "Koppeling verwijderen" (do not press that yet).

### Importeren (4 minutes)
Open **Importeren**, press "Bestand kiezen" (or drop a file) and pick one of the files from `fixtures/csv/`. The steps are Bestand (it says "Lijkt een Argenta-export"), Kolommen (already filled in; under "Naar welke rekening?" pick the account), Controle (three numbers: "nieuw", "al in Saldo", "onleesbaar") and Klaar. Nothing is stored before you press "Importeer N transacties". Every file and its exact result is described in [`fixtures/csv/README.md`](../fixtures/csv/README.md); the short version, each on a fresh demo:

| File | Into | You should see |
|---|---|---|
| `valid.csv` | Zichtrekening | 20 nieuw, 0 al in Saldo, 0 onleesbaar. After "Importeer 20 transacties": "20 transacties geïmporteerd"; the badge on Transacties goes from 4 to 24 and search `apotheek` finds the rows of October 2025. |
| `valid.csv` again | Zichtrekening | 0 nieuw, 20 al in Saldo, "Er komt niets bij: elke rij staat al in Saldo of is onleesbaar." and the import button is disabled. |
| `overlap.csv` | Zichtrekening | 4 nieuw, 6 al in Saldo, and the warning "4 nieuwe regels vallen in de periode die de bank al synchroniseert; controleer op dubbels." |
| `other-account.csv` | Zichtrekening | 0 nieuw, 12 onleesbaar, each "Rekening BE68 •••• •••• 7034 in het bestand is niet de gekozen rekening." |
| `other-account.csv` | Testrekening | 12 nieuw: the file's account is the one you created. |
| `non-euro.csv` | Zichtrekening | 8 nieuw, 2 onleesbaar: "Regel 4" and "Regel 7", "Alleen bedragen in euro worden ondersteund." |
| `malformed.csv` | Zichtrekening | 6 nieuw, 5 onleesbaar, listed per line (4, 5, 6, 7, 10) under "Onleesbare rijen". |
| `several-accounts.csv` | Testrekening | 4 nieuw, 7 onleesbaar ("Rekening BE71 …" and "Rekening BE62 …" are not the chosen account). |
| `several-accounts.csv` | Reserve | 0 nieuw, 11 onleesbaar: "Het bestand bevat rijen van meer dan één rekening, en de gekozen rekening heeft geen IBAN om ze uit elkaar te houden." |
| `large.csv` | Zichtrekening | 1.500 nieuw, checked and imported in about a second. |

Afterwards the "Geschiedenis" list on Importeren shows each import as a batch. The 60 previews and 20 imports per hour that the server allows are reset by restarting.

### Bank link removal (1 minute, last: it changes the demo)
Open **Bankkoppelingen** (or the Zichtrekening account page from step 3) and press "Koppeling verwijderen". The question "Koppeling met Argenta verwijderen?" offers "Geschiedenis bewaren" (transactions and balances stay, the accounts stop updating) and "Geschiedenis verwijderen" (Zichtrekening and all its transactions go, the 4 to categorise with them; the Gedeelde rekening stays because Partner still uses it). Choose "Geschiedenis bewaren" and confirm with "Koppeling verwijderen": a toast "Koppeling verwijderd · geschiedenis bewaard" appears; Bankkoppelingen now says "Nog geen bank gekoppeld"; Zichtrekening and Gedeelde rekening stay, with all their transactions, marked "Argenta · niet meer gekoppeld" on Rekeningen and Start; the alert "Toestemming verloopt over 12 dagen" is gone. Run `scripts/dev.ps1 -Stop`, then `scripts/dev.ps1 -Fresh` to get the link back.

## Added in 0.4: categorisation

Categories, rules and suggestions. The detail in Transacties (a side panel on a wide screen, a bottom sheet at phone width) is no longer read-only: you pick the category, apply it to similar transactions and make a rule, add a note and split a booked transaction. **Categorieën en regels** (Meer) manages the category tree, the rules and the suggestions. The two parts below each start from a fresh demo, so run `scripts/dev.ps1 -Stop` and then `scripts/dev.ps1 -Fresh` before each of them. At phone width the detail and the editors open as bottom sheets that close after saving; on a wide screen the editors are a side panel.

### Categorise in Transacties (about fifteen minutes)

Start on a fresh demo and open http://localhost:5180. Each item is "do this, you should see that". The items build on each other and change the demo's data; the numbers assume a fresh demo and this order.

1. **Open an uncategorised row.** Open **Transacties**, click the chip "Niet gecategoriseerd 4" and click Bakkerij De Graankorrel (−€ 8,40, Zichtrekening, 17 november). "Categorie" reads "Niet gecategoriseerd". Under "Kies een categorie" you see the pills Wonen, Boodschappen, Vrije tijd, Vervoer, Abonnementen and Overig (money out; an income row shows Salaris, Terugbetaling, Bijdrage and Overig inkomen) and a select "Alle categorieën" with the whole tree (a subcategory reads like "Wonen › Energie"). The box "Toepassen op vergelijkbare en regel maken" is greyed out with "Kies eerst een categorie."; below it are "Splitsen", the field "Notitie" (placeholder "Bijvoorbeeld: verjaardagscadeau") and "Opslaan".
2. **Pick a category.** Tap "Boodschappen". It saves at once, without a toast: the pill gets a check, the strip "Zelf gekozen" ("Regels en suggesties overschrijven dit niet") appears, "Categorie" reads "Boodschappen", the row in the list shows "Boodschappen" (it keeps its place in the filtered list until you change the filter), and the chip and the sidebar badge read 3. The alert on Start reads "3 transacties te categoriseren" too.
3. **A rule and a note.** Tick "Toepassen op vergelijkbare en regel maken". The text under it reads "Nieuwe transacties van Bakkerij De Graankorrel krijgen deze categorie.": no other row of that name exists on your accounts. Type `Zaterdagontbijt` in "Notitie" and press "Opslaan". A toast "Regel gemaakt · 0 andere bijgewerkt" appears (at phone width the sheet closes: open the row again), the note stays in the field, and the strip reads "Via nieuwe regel ‘Bakkerij De Graankorrel’" with "Net gemaakt · staat bij je regels" and the link "Regel bekijken". The link opens Categorieën en regels on the Regels tab with that rule open: one rule, "Tegenpartij bevat ‘Bakkerij De Graankorrel’" → Boodschappen, for "Jij" (a rule of yours, covering the accounts where you are the only member); go back with the browser's Back button. The strip stays until you open another row; after that the row reads "Zelf gekozen" again: a rule made from a row never replaces your own pick on that row. A change of only the note answers with the toast "Opgeslagen".
4. **Split a booked row.** Click Frituur 't Pleintje (−€ 14,50, 15 november) and press "Splitsen". The editor "Splitsen" shows the amount, two parts ("Kies een categorie" and "0,00"), "Nog te verdelen € 14,50" and the hint "Verdeel het hele bedrag om op te slaan." ("Opslaan" then only shows that hint as a toast). Type `10,00` in the first part: "Nog te verdelen € 4,50". Type `12,00` in the second: "Te veel verdeeld € 7,50" with "Samen is dat meer dan het bedrag van de transactie." Change it to `4,50`: "Nog te verdelen € 0,00" with a check and the hint "Kies voor elk deel een categorie." Choose Boodschappen for the first part and Overig for the second ("Deel toevoegen" adds up to ten parts) and press "Opslaan": toast "Gesplitst over 2 categorieën". The detail now shows "Verdeling" with both parts and "Splitsing aanpassen"; "Categorie" and the row read "Gesplitst · 2 categorieën"; the badge reads 2 (a split row is not "te categoriseren"). Press "Splitsing aanpassen", then "Splitsing ongedaan maken": toast "Splitsing ongedaan gemaakt", Frituur 't Pleintje is "Niet gecategoriseerd" again (a row that had its own category gets it back) and the badge reads 3.
5. **Apply to similar rows.** Import `fixtures/csv/valid.csv` into Zichtrekening (Importeren, as above): 20 nieuw, and the badge reads 23. Open Transacties without filters, choose the account "Zichtrekening" and search `colruyt`: the three Colruyt rows of October 2025, −€ 48,60 (26 okt), −€ 91,07 (14 okt) and −€ 76,32 (4 okt), all "Niet gecategoriseerd". (The Colruyt rows of the Gedeelde rekening are not in this list: they belong to another account.)
   - Open the row of −€ 76,32 and tap "Overig" (the wrong category, on purpose): the badge reads 22.
   - Open the row of −€ 91,07 and tap "Boodschappen": the badge reads 21. Under the box you read "Ook 1 andere transactie van Colruyt Laagste Prijzen krijgt deze categorie." and "1 overgeslagen: 1 zelf gekozen · die blijven staan.": the row of −€ 48,60 will change, the row of −€ 76,32 is your own pick and stays.
   - Tick the box and press "Opslaan": toast "Regel gemaakt · 1 andere bijgewerkt · 1 overgeslagen: 1 zelf gekozen". The row of −€ 48,60 now reads "Boodschappen", the row of −€ 76,32 still "Overig", and the badge reads 20. The Colruyt rows of the Gedeelde rekening did not change: a rule of yours covers only the accounts where you are the only member.
6. **The next import follows the rule.** Import `fixtures/csv/overlap.csv` into Zichtrekening: 4 nieuw, 6 al in Saldo and the overlap warning (as in the table above). In Transacties (Zichtrekening, search `colruyt`) you now see four Colruyt rows: the new one of 21 oktober 2026 (−€ 68,75) arrived as "Boodschappen", with the strip "Via regel ‘Colruyt Laagste Prijzen’" and the link "Regel aanpassen" (it opens that rule). The other three new rows, Lidl (−€ 41,20), Apotheek Peeters (−€ 12,50) and Delhaize (−€ 39,80), have no rule and arrive "Niet gecategoriseerd": the badge reads 23.
7. **Repair after a wrong pick.** Open the Colruyt row of −€ 91,07 and tap "Vrije tijd" as if that were the mistake. Under the box you read "Ook 2 andere transacties van Colruyt Laagste Prijzen krijgen deze categorie." and "1 overgeslagen: 1 zelf gekozen · die blijven staan." Tick it and press "Opslaan": toast "Regel bijgewerkt · 2 andere bijgewerkt · 1 overgeslagen: 1 zelf gekozen". Now tap "Boodschappen", tick the box and press "Opslaan" again: the same toast, and the rows follow back to "Boodschappen". There is no undo button; this is the repair path. The Regels tab of Categorieën en regels still lists one Colruyt rule next to the Bakkerij one: the rule was reused ("Regel bijgewerkt"), not duplicated.
8. **A shared account.** Press "Wis filters" and keep the search `colruyt`: the row on top is Colruyt Laagste Prijzen of 18 november (−€ 86,42, Gedeelde rekening, "Gedeeld"). "Categorie" reads "Boodschappen" and the strip "Uit je importbestand" (the demo's history counts as imported: neither rules nor suggestions replace it). Under the field "Notitie" you read "Zichtbaar voor iedereen met toegang tot deze rekening", and under the box "Nieuwe transacties van Colruyt Laagste Prijzen krijgen deze categorie. De regel geldt voor alle leden van de Gedeelde rekening." (an account rule, not a rule of yours; no line about skipped rows, since every other Colruyt row of that account already has Boodschappen). Tap "Boodschappen": the strip becomes "Zelf gekozen", because a pick over an imported category makes it yours. Leave the box unticked (ticking it would make that account rule: "Regel gemaakt · 0 andere bijgewerkt").
9. **A pending row.** Clear the search and click Bol.com ("In behandeling", −€ 24,99, 18 november). You read "Nog in behandeling. Telt mee in de totalen zodra de bank ze boekt." The pills work (a pending row can be categorised), but "Splitsen" is greyed out with the hint "Splitsen kan pas als de bank de transactie boekt." under it; pressing it shows that sentence as a toast. A category you chose and a note on a pending row go with it to the booked row when the bank books it. The demo cannot show that (its sync brings no new rows); the server test `TestCarryPendingToBooked` (`server/internal/ledger/carry_test.go`) does.
10. **Offline.** With a detail open, turn the network off in the browser's devtools (Network, "Offline"). You see "Je bent offline. Opslaan kan weer zodra je verbinding hebt." above "Opslaan"; the pills, the box, the field "Notitie" and "Opslaan" are disabled, and pressing a pill shows the toast "Je bent offline · wijzigen kan weer zodra je verbinding hebt". Turn the network on again and everything works again.

The read-only view (a member with read permission sees the category, split and note, the chip "Alleen lezen" and the line that says who gave the read right, but no edit controls) cannot be reached with the demo data, where you hold edit rights on every account you see; the web tests (`TransactieDetail.test.tsx`) cover it.

### Categorieën en regels (about fifteen minutes)

Start on a fresh demo, open http://localhost:5180 and import `fixtures/csv/valid.csv` into Zichtrekening (Importeren: 20 nieuw, then "Importeer 20 transacties"). The badge on Transacties reads 24. The three tabs build on each other: Categorieën and Regels together end back at this state (the default tree, no rules, 24 to categorise), so the numbers of Suggesties hold if you keep the order.

### What a rule can hold
Besides the category (required): a counterparty ("bevat" or "is gelijk aan"), a counterparty IBAN, a communication ("bevat" or a regular expression), an amount range (cents in the API, compared on the absolute amount), an owner (`accountId`; none means yours, applying to your personal accounts, the accounts where you are the only member) and a priority (higher wins, a tie goes to the newest rule; the arrows or "Prioriteit" renumber it). A rule applies to rows that come in through a sync or an import; "Ook toepassen op bestaande transacties" (`POST /api/rules/{id}/apply`) applies it to the rows already stored. A category chosen by hand is never overwritten, nor one that came from an import file, nor a split. The contract is in [api.md](api.md).
