# Changelog

## Unreleased (0.5)
- Batches and undo (0.5-5): every import in the Importeren history, and the result right after it, has "Ongedaan maken". Saldo first counts what goes: how many transactions are removed (with their category, splits and notes) and how many of them you changed yourself, and that categories created by the import or taken over by existing transactions stay. Confirm and the file's transactions are gone in one step; manual and synced transactions are never touched, and the same file imports again in full afterwards. A file that went to several accounts is one entry with "Alles ongedaan maken". An import that added nothing (the same file again) stays in the history as "Niets nieuws toegevoegd" without a button; an undone one says "Ongedaan gemaakt op ...".
- Overlap and duplicates (0.5-4): the Controle step of a Bilance import now helps your old history fit with what the bank already synced. For each account it suggests a cutoff, the first date the bank synced (you can change it or choose "Geen afkapdatum"): rows from that date on are skipped and counted. Rows that look like a transaction you already have (same amount, at most a day apart, a similar name) are shown side by side as probable duplicates and skipped, unless you choose "Toch importeren" per row or "Alles opnemen". When such an existing transaction has no category, it takes the category from the file (never over one you chose, a rule or a split); the result says how many. The cutoff and the duplicates only apply to a Bilance file; any other CSV keeps the exact-match rule and its warning. The update changes no data model.
- Category mapping (0.5-3): the Categorieën step of the import wizard now maps every category of the file onto Saldo's categories. Each pair (Categorie, Subcategorie) goes to an existing category, to a new one (name, place and icon of your choice), or stays without; choosing the same category for several pairs merges them, and "Per hoofdcategorie koppelen" gives all subcategories of one main category the same target. Saldo suggests a category by name and shows it, and remembers what you chose per source: a second Bilance import opens with every known category marked "Opgeslagen". New categories are only made when the import goes through. Imported transactions get the category with origin "import", which rules and suggestions never overwrite; the check and the result say how many get a category. The mapping can be read and changed afterwards and re-applied to a batch through the API (no screen yet). The update rebuilds the empty category mapping table and adds two empty columns to the transactions table; no existing data changes.
- Import wizard and Bilance preset (0.5-2): Importeren recognises a Bilance export and fills in the columns, including the note, the two category columns and the account name. The wizard has five steps now (Bestand, Kolommen, Categorieën, Controle, Klaar): the delimiter, encoding, date format and decimal separator can be set by hand, a file with an account column (Bilance's `Rekening(en)`) maps each account name to one of your accounts and makes one batch per account, and Categorieën lists the categories of the file (mapping them follows in the next step of this version). Of a card payment only the merchant, date and place are kept: the card holder and the card number are never stored outside the raw row. A file may now be up to 20 MB and 100 000 rows (was 5 MB and 20 000). The update changes no data and adds no migration.

## Unreleased (0.4)
- Categories: one category tree for everyone, two levels, with the Dutch default set added once on the first start of this version (Wonen, Boodschappen, Vrije tijd, Vervoer, Abonnementen, Overig with their subcategories; Salaris, Terugbetaling, Bijdrage, Overig inkomen). Add, rename, move, recolour and remove them on the Categorieen en regels screen in Meer; removing asks where its transactions go (another category, which is also how two categories are merged, or uncategorised).
- Rules: categorise by counterparty (contains or equals), counterparty IBAN, communication (contains or a regular expression) and amount range, per account or for your own personal accounts, with a priority. New synced and imported transactions get the category of the first matching rule; "apply" runs the rules over what is stored. A category you chose yourself or one from an import is never overwritten. The update adds two columns to the rules table and changes no existing data.
- Categorise in Transacties: change the category of a transaction in a tap (the pills of the main categories or the full list, a pending transaction too), tick "Toepassen op vergelijkbare en regel maken" to give the similar transactions that category and make a rule for new ones (it says how many change and how many stay: a category you chose yourself, one from an import and a split are never replaced), add a note (at most 200 characters, visible to everyone with access to the account) and split a booked transaction over several categories. A category you chose on a pending transaction, and its note, now carry over when the bank books it. Read-only members of a shared account see the category and the note but cannot change them. The update changes no data.
- Categorieen en regels (Meer): manage the categories and your rules in one place. Reorder the rules with the arrows, see how many transactions a rule matches before you save it, tick "Ook toepassen op bestaande transacties" to apply it to what is already there (a category you chose yourself, one from an import and a split are never replaced), and open a rule from "Regel aanpassen" in a transaction. Suggestions: a counterparty you categorised before gets the category you chose most often; "Bevestigen" categorises the transactions that wait now and makes a rule for new ones (on your personal accounts only; an equivalent rule is reused, and a rule for that counterparty with another category is left alone and mentioned), "Als regel" opens the rule editor filled in to adjust first, and "Negeren" dismisses it for good. Meer shows "N suggesties om te bevestigen". The browser's own dropdowns are replaced by one designed dropdown. The update adds a unique index on the suggestions table and changes no existing data.
- Category icons: every category and subcategory has an icon, chosen in the category editor on the Categorieen en regels screen (49 to choose from; the default categories start with a fitting one, a category without one shows a tag). The colour stays that of the main category. The update adds one empty column to the categories table and fills in the icons of the default categories; no other data changes.

## 0.3.0
- Transacties: every synced transaction by day with the account colour and pending rows, search on name, amount and communication, filters for account, period and category, "Oudere transacties laden", and a read-only detail.
- Rekeningen: name, colour and minimum buffer per account, an account page with balance history, settings, sync status and recent transactions, manual accounts (savings, or a current account without a bank link) with a hand-updated balance and its history, "Rekening toevoegen", and removing your bank link while keeping or deleting the history. Removing a link waits at most 30 seconds for a running sync, then answers that it is busy and removes nothing.
- Start: the balance per account against its own buffer, Persoonlijk and Gedeeld sections with sync status, the sync button with progress, the alerts for an expiring consent and a stale or failed sync, and welcome steps that follow what you have done so far.
- CSV import (Importeren in Meer): upload a CSV, check the columns, choose the account, see the counts, import. A preset recognises the Argenta export; the file's own account and currency are checked, rows already in the account are skipped (also when the bank sync brings them later), and importing the same file again adds nothing. Every import is kept as a batch. There is no undo yet. The preset is built from the header only: check the first import against your real export.
- Fixes: "Onder de buffer" counts calendar days, an ambiguous amount in the search is ignored instead of guessed, "Deze maand" and "Dit jaar" show future-dated pending rows, and a link removed in another tab can no longer come back active.
- Sync engine: a nightly sync around 04:00 that catches up after a restart or a Home Assistant backup, retries a failed night with backoff, and syncs every account on its own. "Nu synchroniseren" and the first sync after linking run in the background; the web app follows them. A pending transaction is replaced when the bank books it, and a failed sync deletes nothing. The database copy kept before this update protects the one data change: older duplicate balances of the same day are merged.
- Reminders: e-mails "Koppeling verloopt" at 14 and 3 days and "Synchronisatie gestopt" (consent lapsed, or no good sync for 3 days), each sent once; a red alert on Start for a stopped sync.

## 0.2.2
- Fix: Bankkoppelingen and Meer failed with an error as soon as the Enable Banking key was saved. A link that is not finished yet has no consent dates, and the pages tried to show them. They now show "Niet afgerond".

## 0.2.1
- Fix: Rekeningen failed with an error for a user without accounts (for example before the first bank link), because the accounts list answered `null` instead of an empty list. It now shows "Nog geen rekeningen".

## 0.2.0
- First add-on build: the Go server with its database, health check and the web app shell.
- Sign-in: e-mail and password plus an 8-digit e-mail code, trusted devices (90 days), first-admin setup link in the log, invitations, admin reset links and admin recovery. New options for the mail server (`smtp_*`, STARTTLS or TLS only) and `admin_recovery`.
- Bank link: Enable Banking application id and key under Instellingen (stored sealed with a key file in `/data`), Bankkoppelingen with the linking wizard and re-authorisation, the first sync of transactions and balances, "Nu synchroniseren". Redirect URL to register at Enable Banking: `<public_url>/bankkoppelingen/terug`.
- Security: `Secure` cookie behind Cloudflared, HSTS with an https `public_url`, sign-in links kept out of the log, Go 1.27.3 toolchain. See `docs/security-baseline.md`.
- Not yet checked against a real bank: the Enable Banking client is built from the public docs (spike S1 comes next), so link a bank only after that check and the security checklist in the add-on documentation.
